## Story

**As an** `lp-forge` operator,
**I want** Phase 6 to generate a working Next.js 15 application that preserves the source brand (logo, colors, fonts, hero imagery from `brand-spec.md`) while applying one of 6 distinctive aesthetic directions and rewriting copy from grounded `business-spec.md`,

## Acceptance Criteria

### Code Generation Foundation

1. **AC-1 — Next.js base template:** `templates/nextjs-base/` contains a Next.js 15 + TypeScript + App Router scaffold. Builds clean from a fresh `npm install && npm run build`. Includes: `app/layout.tsx`, `app/page.tsx`, `app/globals.css`, basic `components/`, `public/brand/.gitkeep`, `next.config.mjs`, `tsconfig.json`, `package.json` with curated deps.
2. **AC-2 — Direction-aware sub-templates (per Aria Amendment A-3: ALL directions use Tailwind; split is on shadcn only):** `templates/directions/` has 6 sub-template overlays:

   | Direction | Tailwind | shadcn | Distinguishing config |
   |---|---|---|---|
   | `industrial/` | ✅ | ✅ (Card, Button, Input) | monospace display + grid-heavy layout |
   | `luxury/` | ✅ | ✅ (full primitives) | refined serif+sans + generous spacing |
   | `playful/` | ✅ | ✅ (Card, Button, Badge) | sans+display + rounded + color-rich |
   | `organic/` | ✅ | ✅ (Card, Button) | warm palette + gentle motion |
   | `editorial/` | ✅ | ❌ (custom from scratch) | 12-col asymmetric grid + drop-cap utilities + serif display |
   | `brutalist/` | ✅ | ❌ (custom from scratch) | harsh-border utilities + no shadows + raw sans |

   Each overlay defines: `globals.css` modifications, `tailwind.config.ts` extensions, 2-3 reference `components/` patterns. The 2 shadcn-less directions (editorial, brutalist) use Tailwind `@layer` directives extensively + bespoke `components/` written without shadcn dependencies.
3. **AC-3 — Project assembler:** `lib/nextjs-generator.cjs` orchestrates:
   1. Copy base template to `outDir/redesign/`
   2. Overlay chosen direction's files (atomic merge)
   3. Copy brand assets from `outDir/assets/brand/` → `outDir/redesign/public/brand/`
   4. Inject brand tokens from `tokens.json` into `globals.css` as CSS custom properties
   5. Generate sections (hero, services, about, contact, footer) via LLM calls grounded in `business-spec.md`
   6. Replace template placeholders with generated content
   7. Run `npm install` in `outDir/redesign/` (cached if package.json unchanged)
   8. Run `npm run build` — must exit 0 (failure → exit code 10)

### Brand DNA Preservation

4. **AC-4 — Logo wired:** `<img src="/brand/logo.svg">` (or .png) appears in `app/components/Header.tsx` — referenced as static asset, never reimplemented as CSS/SVG silhouette. (Hard rule from huashu §1.a.)
5. **AC-5 — Hero imagery wired:** If `brand-spec.md` lists hero images, they appear in `app/page.tsx` hero section. If absent, hero is **text-only** with bold typography — never a stock photo fallback (huashu §9.5).
6. **AC-6 — Colors wired:** Top 3 colors from `tokens.json` injected as `--brand-primary`, `--brand-accent`, `--brand-ink` CSS custom properties in `globals.css`. Direction-specific overlays use these via `var(--brand-primary)` — never hardcoded HEX.
7. **AC-7 — Fonts wired:** Two fonts loaded (display + body):
   - If source fonts are in `data/forbidden-fonts.yaml` → picker selects from `data/curated-font-pairs.yaml` matching the direction
   - Else → use source fonts via `next/font/google` (or local @font-face if not Google)
   - Both injected via Next.js font optimization

### Copy Grounding (Anti-Hallucination)

8. **AC-8 — Copywriter from business-spec only:**
   - `lib/copywriter.cjs` takes `business-spec.md` parsed object + chosen direction's tone-guide
   - Generates: hero headline (1 line), hero subhead (1-2 lines), 3-5 service cards, about paragraph, footer copy, CTA labels
   - **Hard rule:** every output sentence must reference a fact in business-spec. LLM prompted to mark any inferred fact with `<!-- INFERRED -->` HTML comment; final assembler strips comments but warns if N > 0 in `validation-report.json`
9. **AC-9 — Pricing absent? Don't invent:**
   - If `business-spec.md` has no pricing → no pricing section in generated site. **Period.** No "A partir de R$X" placeholders.
10. **AC-10 — Hours absent? Honest "Consulte" CTA:**
    - If hours missing, footer shows "Consulte horários" linking to WhatsApp/phone, never "Aberto 24h" by default

### Anti-Slop Discipline

11. **AC-11 — Anti-slop linter:** `lib/aesthetic-lint.cjs` scans generated `redesign/`:
    - **CRITICAL violations (block exit 0):**
      - Forbidden font as display (Inter/Roboto/Arial as `<h1>` font when source didn't use it)
      - Purple gradient background as hero (`linear-gradient(..., #*purple* ..., #*white*)`)
      - Emoji in headlines or section labels
      - SVG-painted faces / illustration (any inline `<svg>` containing `path` data resembling humanoid features — heuristic: viewBox 0-200, 5+ paths, presence in hero)
      - CSS silhouette of product (no real `<img>` from `public/brand/` in hero, but custom `<svg>` shapes there instead)
    - **WARNING violations (log, don't block):**
      - More than 3 colors in palette (signals "lacking commitment")
      - Generic "Lorem ipsum" or `[placeholder]` leftover
      - `<i class="fas fa-*">` emoji-icon-like-decoration
12. **AC-12 — Direction commitment verification:**
    - LLM self-rubric: at end of generation, send `redesign/app/page.tsx` + `globals.css` back to LLM with rubric "Does this match the `<direction>` aesthetic? Score 1-10 per axis." Stored in `validation-report.json`.
    - Hard min: each axis ≥ 6/10 or fail with exit 11 (validator phase 7 reports this).

## Dev Notes

- **Direction overlays are design artifacts not just code** — each `templates/directions/<name>/` should ship with 1-2 sample screenshots in `_design-refs/` showing what the direction looks like at its best. `@ux-design-expert` curates these.
- **LLM code-gen vs. template + content injection:** we use **templates with content injection**, not pure LLM code-gen. Reason: pure LLM code-gen of an entire Next.js project is unreliable (broken JSX, missing imports). Template + LLM content = deterministic structure + creative copy.
- **The 6 directions are not "themes":** they imply different layouts, font categories, motion philosophies. `editorial` has a 12-col asymmetric grid; `brutalist` has a single-column harsh layout. Don't conflate them with color swaps.
- **CSS variables vs. Tailwind:** 4/6 directions use Tailwind + CSS vars side-by-side (Tailwind for layout utilities, CSS vars for brand colors). `editorial` and `brutalist` use bare CSS exclusively — no Tailwind — because their aesthetics conflict with utility-class soup.
- **Asset path discipline:** `redesign/public/brand/logo.svg` etc. Never `redesign/components/Logo.tsx` with an inline SVG copy of the logo.
- **Inferred-fact handling:** if LLM produces "Famosa pela feijoada de sábado" but business-spec doesn't list specialties, the `<!-- INFERRED -->` comment must wrap it. Stripped before save but counted. > 3 inferences in single page = warning.
- **Iteration loop:** if `npm run build` fails (exit 10), captured error is sent to LLM with the broken file → 1 retry. Second failure = hard fail with broken file path in stderr.

### Risks
- **Build failures from generated code** — most likely cause: bad JSX from LLM in section overrides. **Mitigation:** templates own all imports; LLM only fills designated `{{HEADLINE}}` `{{SERVICE_LIST}}` placeholders, never writes JSX structure.
- **Direction monoculture** — 80% of restaurants → editorial. **Mitigation:** `direction-picker.cjs` (from 2.4) allows multi-value in YAML; tie-broken by fingerprint variance.
- **Lighthouse < 90** on weak host machine for dev mode — **Mitigation:** AC-14 explicitly tests `npm run build` then `npm run start` (production server), not dev mode, for the gate.
- **next/font fails for non-Google fonts** — **Mitigation:** fallback to `@font-face` with locally-hosted font files in `public/fonts/`. Loader function in `lib/font-loader.cjs`.
