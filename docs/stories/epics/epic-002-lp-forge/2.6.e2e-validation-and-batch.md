## Acceptance Criteria

### Phase 7: Validation

1. **AC-1 — Brand-DNA drift check (inverse design-md):**
   - Validator runs `vendor/design-md/run.cjs --url file://<redesign-build-output> --compare <outDir>/brand-spec.md` semantics: extract tokens from generated site, compare against captured brand-spec
   - Verdict: `in-sync` / `minor-drift` / `notable-drift` / `major-drift` written to `validation-report.json`
   - Hard rule: `major-drift` = exit 11 (warning by default; `--strict` makes it block)
2. **AC-2 — Aesthetic lint final pass:** `aesthetic-lint.cjs` from 2.5 runs as part of Phase 7 (not 6) so it sees the FULL built output. Result joined into `validation-report.json`.
3. **AC-3 — Direction commitment final score:** 5-axis LLM rubric from 2.5 runs as final gate; results saved.
4. **AC-4 — Build + boot smoke:**
   - Validator runs `npm run build` in `redesign/` — must exit 0
   - Validator boots `npm run start` in background, hits `localhost:PORT/`, expects HTTP 200 with HTML containing the business name from `business-spec.md`
   - Times out at 60s; failure exits 11

### Batch Mode

5. **AC-5 — Batch CLI (per Aria gap G-6 with slug uniqueness check):**
   - `node run.cjs --batch tests/fixtures/batch-urls.txt` reads URLs (one per line)
   - Default concurrency 3; configurable via `--concurrency=N` (max 10)
   - Each URL gets its own outDir under `outputs/lp-forge/{slug}/`
   - **Pre-flight slug uniqueness check (NEW per G-6):** before starting batch, compute slugs for all URLs; if collisions detected, fail-fast with exit 1 and report duplicates. Operator deduplicates input file.
   - Per-URL isolation: failure in URL N does NOT poison URL N+1 (each runs in its own context object)
   - Failures don't abort the batch — they're logged via `lib/logger.cjs` and counted
6. **AC-6 — Batch report:**
   - At end, prints summary: `[batch] 12/15 succeeded · 2 content-gate failures · 1 brand-asset failure`
   - Writes `outputs/lp-forge/_batch-<timestamp>.json` with per-URL status + outDir paths
7. **AC-7 — Resume on failure:**
   - `--batch-resume <batch-id>` re-runs only the failed URLs from a prior batch
   - Successful URLs are skipped (phase-cache makes them fast even without skip)

## Dev Notes

- **Why validation is its own phase:** keeps Story 2.5 focused on generation; lets validation evolve independently (future v2 might add Lighthouse-via-Playwright, accessibility audits, SEO checks).
- **Why batch is here, not earlier:** single-URL flow must be rock-solid first. Adding concurrency on top of a flaky pipeline = nightmare debugging.
- **`p-limit` vs custom semaphore:** use `p-limit` (well-tested, ~10 lines added to deps). Don't roll your own.
- **The manual smoke is the gate** — automated tests give correctness, but only human review gates "is this usable on a real prospect". Both must pass.
- **Vercel deploy:** not a hard AC. If `vercel` is on PATH and operator wants to test: `cd outputs/lp-forge/{slug}/redesign && vercel`. Documented in README, not blocking.
- **CHANGELOG format:** Keep-a-Changelog style. v0.1.0 entry lists epic 002 as the inaugural release.

### Risks
- **Real-URL smoke fails:** likely means one of stories 2.3/2.4/2.5 has a gap. Acceptable — story 2.6 returns to InProgress, the gap goes back to its owning story.
- **Portability test surfaces missing deps:** acceptable. Fix in 2.6 before release.
