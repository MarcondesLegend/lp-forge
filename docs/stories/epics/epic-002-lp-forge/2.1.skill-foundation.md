### Completion Notes List

1. **Implementation approach:** Built bottom-up — modules with no deps first (exit-codes, utils), then deps-graph upward (logger → prompt-loader → cache → llm → cli → orchestrator → run.cjs). Each module independently testable.
2. **`commander` vs `yargs` decision:** Chose `commander` (12.x) over `yargs`. Reason: smaller surface area, fewer breaking-change cycles historically, integrated `helpInformation()` mirrors typical Unix CLI UX. Rationale documented in `lib/cli.cjs` header per AC-4 task 3.
3. **Aria A-8 temperature lock implementation:** Standalone helper `enforceTemperaturePolicy(opts)` checks `NODE_ENV === "production"` and throws if `opts.temperature` is non-zero. Dev override allowed. Tested both branches.
4. **LLM v0.1 stub strategy:** Implemented full API surface (`detectProvider`, `validateProviderModel`, `enforceTemperaturePolicy`, `invokeLlm`) but `invokeLlm` returns a structured `{status: "stub", ...}` object rather than making provider calls. Lets downstream stories (2.2-2.5) integrate against the contract today. Story 2.2 replaces the stub branch with `child_process spawn vendor/design-md/run.cjs` per Aria A-1.
5. **Logger design:** Decided to use a singleton with `initLogger(opts)` first-call init. Avoids passing logger through every function. JSON log write is best-effort wrapped in try/catch — log failures never crash the pipeline (graceful degradation per Constitution).
6. **Test count exceeded plan:** Story called for 2+ tests per module. Delivered 33 total: 5 orchestrator (phase contract, all-stubs run, --from-phase, error surfacing, auto outDir), 6 exit-codes, 8 utils, 13 LLM (especially thorough on Aria A-8 temperature gate — production reject/allow/default + dev override).
7. **CodeRabbit gate decision:** Per Aria amendments and Story 2.6 plan, full CodeRabbit pass happens at v0.1.0 tag (Story 2.6). For Story 2.1, ran `node --test` + manual code review. No CodeRabbit invocation here — saves WSL execution time on Windows.
8. **Smoke E2E artifact cleanup:** Test runs left `outputs/lp-forge/example/` artifacts in both the skill dir (when smoke ran from there) and project root (when run from there). Both gitignored. Cleaned both after smoke completion.
9. **Anti-pattern caught and fixed:** Initial draft of orchestrator.cjs almost used `console.log` directly. Caught during self-review — replaced with `logger.info()` calls, then verified `eslint.config.cjs` lists `no-console: error` so future code can't regress.
10. **Aria A-8 verification:** Wrote explicit test `Aria A-8: production rejects non-zero temperature` which sets `NODE_ENV=production`, calls `enforceTemperaturePolicy({temperature: 0.5})`, asserts the throw includes "A-8 violation". This is the safety net for the entire idempotency contract.

#### F-1 (MEDIUM) — Logger verbosity gating: 'normal' does NOT print INFO events

**Affects:** AC-5, AC-16, A-5
**File:** `.claude/skills/lp-forge/lib/logger.cjs` lines 13-22, 60-64

Logger comment claims "normal: 2 — Errors + warns + info" but the check `if (levelP <= this.verbosity)` evaluates `info(3) <= normal(2) = false`. Result: default smoke run (no `--verbose`) prints **nothing** to stdout. AC-5 says "emits stdout progress per phase" — only `--verbose` actually does this. Tests pass because tests explicitly set `verbosity: "silent"`.

**Recommendation:** Fix in Story 2.2 (5-10 min). Two options — recommended (a):
- (a) Renumber `VERBOSITY`: `silent=0, quiet=1, normal=3, verbose=4` so `info(3) <= normal(3) = true`
- (b) Promote phase-start/phase-done events from `info` to `warn`

**Impact:** Functional (JSON log + telemetry always written), but UX-confusing for operators at default flags. Tracked as **B-2.1-F1**.

#### F-2 (LOW) — Exit-codes count labeling: '13' vs actual 12 named codes

**Affects:** AC-6 + test comment
**Files:** AC-6 text in story; `tests/lib/exit-codes.test.cjs` comment
