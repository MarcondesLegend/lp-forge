## Story

**As an** `lp-forge` operator,
**I want** Phases 2 and 3 to capture the source site's logo, hero imagery, UI screenshots, color palette, type system, AND business information (services, hours, contact, social proof) into `brand-spec.md` and `business-spec.md`,
**so that** the analysis report (Story 2.4) and the Next.js generator (Story 2.5) have grounded, real-world inputs and never invent visual identity or business facts.

## Acceptance Criteria

### Phase 2: Brand Capture (huashu §1.a 5-step protocol)

1. **AC-1 — Logo extraction (Step 3.1) — THREE-TIER FALLBACK per Aria Amendment A-4:**

   **Tier 1 — Real logo extraction (huashu Steps 1-3):** Three sequential strategies tried in order, stops on first success:
     1. `<link rel="icon">` href and explicit `<img>` with `class*=logo` / `alt*=logo`
     2. Inline `<svg>` inside top-of-page header / nav (first 800px viewport, contains brand text or is largest by area)
     3. Common paths: `/logo.svg`, `/logo.png`, `/brand/logo.*`, `/images/logo.*`, `/assets/logo.*`
   - LLM eyeball verification: extracted candidate sent to LLM as base64 + prompt "Is this the logo of `<business name>`? Respond YES/NO/UNCERTAIN."
   - On YES → save `assets/brand/logo.{ext}` + `logo-source.txt` (URL + strategy + `tier: 1`)

   **Tier 2 — Typography-based logotype generation (NEW per Aria A-4):** If all Tier 1 strategies fail:
   - Generate SVG wordmark using `<businessName>` (from `business-spec.md` or `--business-name`) styled with:
     - Display font from `tokens.json` (or curated fallback if forbidden)
     - Primary color from `tokens.json`
     - Black-on-light + light-on-dark variants
   - Output: `assets/brand/logo.svg` with comment `<!-- generated-logotype: typography-based fallback, no source logo found at <timestamp> -->`
   - Save `logo-source.txt` with `tier: 2` and font/color used
   - Module: `lib/logotype-generator.cjs` (NEW — implements text→SVG with embedded font via data URL)

   **Tier 3 — Hard-fail:** If Tier 1 fails AND business name is unknown (no `--business-name`, no business name detectable from page) → exit code 8 with hint: `"No logo found and no business name available to generate logotype fallback. Provide --business-name or manual asset."`
2. **AC-2 — Hero / product imagery (Step 3.2):**
   - For each candidate `<img>` in first 1200px viewport with `width >= 800px` (rendered or natural), download up to 3
   - For each, LLM rates 1-10 against criteria: resolution, copyright clarity, brand-fit, composition, narrative role
   - Keep top-2 with score >= 8 → `assets/brand/hero-{1,2}.{ext}`
   - If no image >= 8 → record absence in `brand-spec.md` and continue (NOT a hard-fail; downstream uses text-only hero per huashu §9.5)
3. **AC-3 — UI / interior screenshots (Step 3.3):**
   - Find `<img>` candidates labeled `screenshot`, `interface`, `app`, `dashboard`, `interior`, `produto`, in middle/lower viewport
   - Same 5-10-2-8 scoring; keep top-2 → `assets/brand/ui-{1,2}.{ext}`
   - Honest fallback: if business is service-based (restaurant interior, oficina workshop, salon space) and no UI relevant → skip without flag
4. **AC-4 — Color palette extraction (Step 4):**
   - Run `grep -hoE '#[0-9A-Fa-f]{6}' assets/brand/*.{svg,html} | sort | uniq -c | sort -rn | head -20` equivalent in JS
   - Filter out black/white/grays (luminance check)
   - Cross-reference with `tokens.json` from Phase 1
   - Annotate each color with provenance (logo / CSS var / inferred)
5. **AC-5 — Font system extraction:**
   - From `tokens.json` (Phase 1) + `@font-face` declarations in CSS bundle
   - Identify "display" candidates (large font-size in CSS, used in `<h1>`/`<h2>`) and "body" (default `body` font-family)
   - Verify display fonts are NOT in `data/forbidden-fonts.yaml` (Inter / Roboto / Arial / system); if so, mark as **slot to override** in the generator
6. **AC-6 — `brand-spec.md` writer:**
   - Template from huashu §1.a Step 5 verbatim
   - Filled with: logo paths, hero paths (or "absent — text-only fallback"), UI paths (or "n/a"), color palette with provenance, font stack, signature-detail bullet (LLM-generated 1-sentence), forbidden-zones bullet (LLM-generated 1-sentence), keyword bullet (3-5 adjectives)
   - **Strict format** — generator (Story 2.5) parses this; deviations break downstream
7. **AC-7 — Brand-asset self-audit:**
   - Before exiting Phase 2, run `lib/brand-audit.cjs`:
     - Logo present? (else exit 8)
     - At least 1 token from logo SVG? (else log warning)
     - Brand-spec.md parseable? (round-trip test: parse → re-stringify → compare)

### Phase 3: Business Info Extraction

8. **AC-8 — Business info structured extraction:**
   - Input: `page.md` (from Phase 1's turndown) + optional `--business-name`, `--category`, `--city`
   - LLM prompt with strict JSON schema: `{ businessName, category, city, services[], hours{...}, contact{phone, whatsapp, email, address, social[]}, socialProof[], pricingHints[], differentiators[] }`
   - Fields are nullable; LLM instructed to **NEVER invent** — empty array if not found
9. **AC-9 — `business-spec.md` human-readable output:**
   - Generated from structured JSON via template
   - Sections: Identity, Services, Hours, Contact, Social Proof, Pricing, Differentiators
   - Empty sections explicitly marked `[NOT FOUND ON SOURCE]` — never silently omitted
10. **AC-10 — pt-BR language enforcement:**
    - When `--lang pt-BR`, LLM prompts (in this story) are in Portuguese; outputs are in Portuguese; field names in JSON stay English (parsable)
    - Hour parsing handles BR formats: "Seg-Sex 8h-18h", "Aberto 24h", "Fechado domingo"
11. **AC-11 — Anti-hallucination test:**
    - Test fixture has page.md with ONLY business name + phone, nothing else
    - LLM output must have empty `services[]`, empty `hours`, empty `socialProof[]` — **no invention**
    - Test asserts this is the case
12. **AC-12 — Confidence scoring per field:**
    - Each field annotated with `confidence: high | medium | low` in JSON
    - `high` = explicit quote in page.md; `medium` = strong inference (e.g., "we serve breakfast" → category includes "breakfast"); `low` = guess
    - business-spec.md visually marks low-confidence with `[?]` suffix
13. **AC-13 — Quality gates:** lint, tests, CodeRabbit clean. Two fixture URLs (restaurant + oficina) produce valid `brand-spec.md` and `business-spec.md`.

### Security Hardening (per Aria Amendment A-6)

14. **AC-14 — Prompt injection sanitization (A-6.1):**
   - All source-site text content sent to LLM (page.md, image alt-text, meta descriptions, JSON-LD) is passed through `lib/sanitizer.cjs`
   - Patterns flagged: `(?i)ignore (previous|all) instructions`, `(?i)you are now`, `(?i)system prompt`, `<\|im_(start|end)\|>`, markdown headings nesting LLM-style commands
   - Matched content is wrapped with `[SANITIZED-START]...[SANITIZED-END]` markers before LLM consumption (NOT stripped — LLM may still need it for context, but knows it's suspicious)
   - Each match logged via `logger.warn('prompt-injection-detected', { pattern, location, snippet })`
   - **NEW module:** `lib/sanitizer.cjs` exports `sanitizeForLlm(text, opts)` → `{ sanitized: string, flagged: Array<{pattern, location, snippet}> }`
   - **Hard-block:** if `flagged.length > 10` for a single URL, exit code **13** ("source content overwhelmingly hostile — manual review required")
   - Test: fixture with embedded injection attempt asserts sanitizer marks but doesn't drop content

15. **AC-15 — Image MIME validation (A-6.2):**
   - Every downloaded brand asset passes through `lib/asset-validator.cjs` before save
   - Checks performed:
     - Content-Type header matches file extension
     - Magic bytes (first 8 bytes) match declared type for PNG (`89 50 4E 47 0D 0A 1A 0A`), JPEG (`FF D8 FF`), WebP, etc.
     - For SVG: parsed and **rejected if contains** `<script>`, `<foreignObject>`, `onload=`, `href=javascript:`, or `<image href="http`
   - On rejection: file NOT saved; logged as `logger.warn('asset-rejected', { url, reason })`; treated as "asset not found" (no exit code)
   - **NEW module:** `lib/asset-validator.cjs` exports `validateImage(buffer, contentType, sourceUrl)` → `{ valid: bool, reason?: string, mimeDetected?: string }`
   - Test: fixture with SVG-with-script asset is rejected; pipeline continues

## Dev Notes

- **Vision model usage:** logo verification and image scoring both need vision-capable LLM. `claude-cli` Opus supports it; OpenRouter `claude-haiku-4-5` supports it. Hard-fail with helpful error if user picks a non-vision model.
- **Image download discipline:** never follow `<img src="data:...">` (those are inline; already in CSS bundle). Skip cross-origin without permissive CORS hints. User-agent string matches huashu's recommendation: `Mozilla/5.0` + project identifier.
- **The 5-10-2-8 rule (huashu §3.4):** we don't literally run 5 search rounds. We search **once**, score 10 candidates if available, keep top-2 only if ≥ 8/10. The "5 rounds" abstraction maps to "5 strategies/heuristics" in our static-first context.
- **Why business-spec.md schema is sacred:** Story 2.5's copywriter consumes it. Schema changes here = breaking changes there. Lock schema with a JSON Schema file in `data/business-spec.schema.json`.
- **Forbidden font handling:** if source uses Inter, we record it in brand-spec but **flag it as `display-override: true`** — Story 2.5 picks a curated alternative from the 30-pair library. This is per huashu §6 anti-slop + frontend-design "never converge on common choices".

### Risks
- **Vision API cost** — verifying logo + scoring up to 6 images = ~7 vision calls per URL. Mitigate: 24h cache + early-exit on first YES logo verification.
- **Cloudflare bot block on image CDN** — sometimes HTML loads fine but `<img>` URLs fail. Mitigate: try with same User-Agent; on 403, mark image as `[blocked - manual provision required]` in spec.
- **LLM invents services** — biggest reputational risk. Mitigate: prompt has explicit instruction + few-shot of "empty array correct response" examples + test case AC-11.
