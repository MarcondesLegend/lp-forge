## Story

**As an** `lp-forge` operator,
**I want** Phase 5 to synthesize the outputs of Phases 1–4 into a single `analysis-report.md` deliverable that diagnoses the source site across design, UX, content, conversion, and brand axes,
**so that** I can hand this report to a prospect (or use it as the rationale for the redesign in the same sales conversation).

## Acceptance Criteria

1. **AC-1 — Report structure (fixed sections, in order):**
   1. **Sumário Executivo** — 3 bullets: identidade da marca / nota geral 1-10 / top 3 problemas mais urgentes
   2. **Identidade Visual Capturada** — from `brand-spec.md`: logo, paleta, tipografia, signature details
   3. **Informações de Negócio Capturadas** — from `business-spec.md`: serviços, horários, contato, prova social (com `[NÃO ENCONTRADO]` honestos)
   4. **Diagnóstico de Design** — 5 sub-headers: tipografia, paleta, espaçamento, motion/interação, composição. Cada um com nota 1-10 e justificativa
   5. **Diagnóstico de UX e Conversão** — hierarquia visual, CTAs, fricção, mobile-friendliness inferido do CSS
   6. **Diagnóstico de Conteúdo** — clareza da proposta de valor, prova social, gatilhos
   7. **Arquétipo Detectado** — from `style-fingerprint.json`: nome do arquétipo + 1 parágrafo do que isso significa
   8. **Stack Detectado** — from `stack.json`: framework, libs, hospedagem inferida
   9. **Direção Recomendada** — uma das 6 direções (editorial/industrial/luxury/playful/brutalist/organic) com justificativa de 3-4 linhas
   10. **Resumo de Oportunidades** — top 5 mudanças que o redesign vai fazer (resposta da pergunta "o que vai melhorar?")
   11. **Anexos** — links para `DESIGN.md`, `tokens.json`, `brand-spec.md`, `business-spec.md`, `before-preview.html`
2. **AC-2 — pt-BR voice:** Report is entirely in Portuguese (when `--lang pt-BR`). Tone: professional consultant, not salesy. No "Olá! 👋", no emoji decoration, no "Vamos elevar sua presença digital".
3. **AC-3 — Grounded in captured artifacts:** Every claim references its source artifact. Example: "A paleta principal `#A23F1B` foi extraída do logo SVG (alta confiança — Phase 2 brand-spec.md)". Test: no claim in the report lacks a parenthetical citation.
4. **AC-4 — Direction picker integrated:** Phase 4 (`direction-picker.cjs` from Story 2.1 stub) produces 1 of 6 directions. This story implements the picker fully: `category` + `fingerprint` + `keywords from brand-spec.md` → mapping in `data/category-to-direction.yaml` → final direction + reasoning string.
5. **AC-5 — Numerical scoring with rubric:** Each of the 5 design sub-axes (typography, palette, spacing, motion, composition) has a 1-10 score. Rubric documented in `data/scoring-rubric.md`. LLM prompted with rubric; outputs structured `{ score, reasoning }` per axis.
6. **AC-6 — Top-3 problems / Top-5 opportunities:**
   - Problems: prioritized by impact (LLM-ranked: conversion-blockers > UX friction > aesthetic)
   - Opportunities: must be **actionable in the Next.js redesign**. No "consider a brand refresh" abstract advice — must say "headline H1 will be rewritten from `<current>` to a value-prop framing"
7. **AC-7 — No invented diagnostics:**
   - If site has NO motion (no CSS transitions detected), report says "Motion: nota n/a — site não usa animações" — does NOT invent a score by analogy
   - If site has NO body content (Linktree-style), several diagnoses gracefully mark as `[n/a]`
8. **AC-8 — Length discipline:**
   - Total report length: 800–1500 words (target 1000) — tested with word-count assertion
   - Hard cap at 2000; LLM instructed to compress on overflow
9. **AC-9 — Markdown discipline:**
   - Heading levels: h1 = report title, h2 = sections from §1, h3 = sub-sections only inside §4 and §5
   - No emoji; tables for paleta and scoring; code-blocks for technical bits (HEX values, stack list)
10. **AC-10 — Deterministic seed:** Same URL + same brand-spec/business-spec inputs + same seed = byte-identical report (modulo LLM stochasticity within tolerance). Seed derived from URL hash.
11. **AC-11 — Tests:**
    - Unit: direction picker mapping (table tests for 12+ categories)
    - Unit: report assembler with mocked LLM outputs
    - Integration: against fixtures from 2.2/2.3 — produces non-empty, schema-valid `analysis-report.md`
12. **AC-12 — Quality gates:** lint, tests, CodeRabbit clean.

## Dev Notes

- **Multi-LLM-call composition:** instead of one mega-prompt, this story uses **6 small LLM calls** (one per major section). Smaller calls = lower cost, easier to debug, better grounding. Aggregator stitches results.
- **The `category-to-direction.yaml`** is the soul of the picker. Initial mappings are heuristics — operator can override via `--direction` flag. Future v2 may A/B-test mappings.
- **Tone calibration:** report is for **a sales rep to hand to a small-business owner**. Tone tests: not academic, not salesy, not condescending. The 2 fixture reports go through `@analyst` for sniff-test.
- **The report is a deliverable** — operator may show it to prospect verbatim or paraphrase. Therefore: factual, no flattery, no shaming. "Seu site atual tem [diagnóstico]" not "Seu site é ruim".

### Risks
- **LLM over-criticism** — to look "thorough" the LLM may invent problems. **Mitigation:** AC-7 fixture test + tone calibration prompts + @analyst eyeball.
- **Direction picker oversimplifies** — restaurant ≠ restaurant. Sushi-bar gourmet vs. boteco have very different ideal directions. **Mitigation:** category-to-direction.yaml allows multi-value (`restaurante: editorial | playful` — LLM picks based on captured signals).
